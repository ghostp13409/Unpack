# Unpack (v1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Tauri 2 desktop app where the user drops context (transcripts, emails, notes, text) and Claude Haiku 5.5 creates and maintains a prioritized task list, with a Focus view that says what to work on next.

**Architecture:** Rust backend owns everything stateful: SQLite via rusqlite, file parsers, the Messages API client, op validation, apply/undo. React frontend is thin: a zustand store that mirrors backend DTOs plus pure derived views. Communication is Tauri `invoke` commands returning serde DTOs.

**Tech Stack:** Tauri 2.12, Rust 1.98, rusqlite (bundled), reqwest (rustls), serde/serde_json, serde_with, mailparse, zip, keyring, chrono, uuid, httpmock (tests); Vite 8, React 19, TypeScript, zustand, lucide-react, @fontsource-variable/inter, @tauri-apps/api, @tauri-apps/plugin-dialog, @tauri-apps/plugin-opener, vitest.

**Spec:** `docs/superpowers/specs/2026-11-01-unpack-v1-design.md`

## Global Constraints

- Model default `claude-haiku-5-5`; header `anthropic-version: 2026-10-21`; `max_tokens: 16000`; structured output via `output_config.format = {type:"json_schema", schema}`; never send `temperature`, `top_p`, `top_k`, `thinking`, or an assistant prefill.
- API key only in Windows Credential Manager (keyring service `Unpack`, account `anthropic_api_key`); never in DB or logs.
- Enums on the wire are snake_case strings: status `todo|in_progress|done|dropped`, priority `urgent|high|medium|low`.
- IDs are UUIDv4 strings; timestamps ISO-8601 UTC (`2026-11-01T17:00:00Z`); dates `YYYY-MM-DD`.
- Size guard: total extracted text over 350,000 characters is refused before any API call.
- Frontend: plain CSS with the tokens in spec §5; no Tailwind; Inter bundled; follows system theme by default.
- Commit after every task with a conventional-commit message.

## Review Focus

1. A `.vtt` where one speaker's line spans two text lines (see the sample in spec §3's workspace) must merge into one utterance, not two. Test in Task 4.
2. The model returns a `create` whose `parent_id` is a temp id that was unchecked in Review. Expected: the child is created at top level with a warning, not dropped and not orphaned. Test in Task 7.
3. Undo of an `update` after the user hand-edited the same field must not silently clobber. Expected: `NeedsConfirm` unless `force`. Test in Task 7.
4. An `.eml` that is HTML-only (no text/plain part) must still yield readable text. Test in Task 4.
5. The API returns `stop_reason: "max_tokens"` or `"refusal"` with HTTP 200. Expected: a typed error, never a JSON parse error. Test in Task 6.

### Task 4: Ingest parsers

**Files:**

**Interfaces:**
- Produces (`ingest/mod.rs`): `enum Extracted { Text { filename: String, text: String }, Pdf { filename: String, base64: String } }` (Serialize); `enum IngestError { Unsupported(String), Read(String), Parse(String) }` (thiserror, Display gives a user sentence like `Unsupported file type ".xlsx"`); `fn extract_file(path: &Path) -> Result<Extracted, IngestError>` dispatching on lowercase extension: `txt|md|json|csv` → read as UTF-8 (lossy); `vtt` → `vtt::compact`; `eml` → `eml::extract`; `docx` → `docx::extract`; `pdf` → base64 of bytes; else `Unsupported`. - `docx::extract(bytes: &[u8]) -> Result<String, IngestError>`: open zip, read `word/document.xml`, `</w:p>` → newline, `<w:tab/>` → tab, strip tags, decode the same entities.
